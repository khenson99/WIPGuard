# Lichen Precision — Airtable ⟷ Arda Cloud eId mapping

Recovered 2026-08-18 from `/tmp/lichen` (volatile scratch space) and committed here so the
work survives. Generated by a Claude Code session on **2026-08-14 / 2026-08-15**.

## Why this exists

Lichen's tool library lives in Airtable. Their catalog has already been loaded into
Arda Cloud tenant `2ae2243c-c2dc-4cbc-868a-cd5411bcd909` (846 items / 846 kanban cards, 1:1).
The **migration is done**; what remains is the ongoing sync.

The blocker: **no join key survived the load.** Nothing in Arda links an item back to its
Airtable record — `internalSKU` is populated on ~4/500, supplier SKU does not exist in Arda's
item model, and the Coda `Airtable Record` column did not propagate. Name is the only viable key.

This directory is the name-matching backfill that reconstructs that join.

> Run the backfill **before** any sync goes live. A create-path sync without it will
> duplicate ~628 tools that already exist in the tenant.

## Known gotchas

- External IDs live in **Coda**, not Arda. The bridge is only as durable as that Coda doc —
  do not let it get copied or forked.
- The Coda Tenants sync table reports 0 orders for every tenant; it cannot see the data.
  Never conclude tenant state from it — query the API.
- Backend: CSV upload-job `ACTION_UPDATE`/`ACTION_DELETE` are broken
  (`Mappers.ItemRow.domain()` hardcodes `eId = TypeId()` and ignores `payload.eid`).
- Backend: `JobEvent.Completed` always reports successCount=0/errorCount=0.
